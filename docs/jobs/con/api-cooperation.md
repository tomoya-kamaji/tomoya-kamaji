### 概要

- 自社サービスの医療向け電子同意書と電子カルテをつなぐ連携 API のセキュリティ設計と実装をリード

### 背景

- なぜこの実装が必要だったか
  - 電子カルテ連携の実運用実績がなく、セキュリティ要件の高い医療機関に導入障壁があった
  - 以降の導入で再利用できる標準と手順を確立するため

### 役割・体制

- セキュリティ設計〜実装〜検証〜運用フロー整備までを単独主導
- 認証局選定や証明書発行プロセスでベンダーと折衝、仕様合意をドライブ

### 発揮したバリュー

- インフラ制約で一般的な相互認証が使えない中、
  アプリケーション層での証明書検証と API キーによる多層防御を設計
- 認証局を比較・選定し、ベンダーと要件定義・仕様の合意を獲得
- 誤用リスクを下げるエンドポイント責務の整理

### 技術的な取り組み

- 鍵・証明書のローテーションを前提とした認証方式の設計・実装
- 例外ハンドリング標準化と、検証失敗を追跡できる監査ログの設計

### 成果・インパクト

- 本番運用で 1 年間インシデント 0
- 医療機関での導入を現地立会いで成功、現場から「業務が効率化した」と評価を獲得
- 以降の医療機関向け連携の標準手順・実装テンプレートとして再利用可能に

### 使用技術・ツール

- Node.js（Express）、Google Cloud
