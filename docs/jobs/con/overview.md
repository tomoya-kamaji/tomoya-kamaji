## プロダクト概要

「医療機関様」と「患者様」を繋ぎ、電子同意書や医療向け説明動画の配信、入退院プロセスの支援を行う医患連携 SaaS を開発

## 雇用形態・体制

- 2024 年 3 月〜2024 年 9 月 フルタイム業務委託
- 2024 年 10 月〜2026 年 2 月 正社員（株式会社 Matataki と並行稼働）
- チーム構成：PdM 1 名、テックリード 1 名（自分）、エンジニア 3 名、デザイナー 1 名

## 主な担当業務

■ テックリード・開発プロセス改善

- 機能開発におけるアーキテクチャ・仕様の設計支援およびコードレビュー
- 軽量な設計プロセス（API 仕様・データモデル定義）と PR 運用ルールの策定・定着
- 開発メンバーとの 1on1 の実施とチーム全体の品質向上

■ 機能開発・セキュリティ・運用基盤強化（Nuxt.js × Express × Google Cloud）

- 電子同意書と電子カルテを繋ぐ連携 API のセキュリティ設計・実装（API キー + クライアント証明書の多層防御）
- 医療向け説明動画配信機能の再設計と基盤刷新のリード
- 入退院プロセス支援機能群の設計リード・実装
- LINE 連携を含むユーザー中心のアカウント設計の推進
- オブザーバビリティ強化（Cloud Logging、Sentry、トレーシング、Slack アラート整備）

■ 開発以外の業務

- 医療機関・電子カルテベンダーとの仕様折衝、認証局選定および証明書発行プロセスの調整
- 医療機関での連携導入における現地立会い・導入支援
- ビジネスサイドの商談への同席と、システム観点からの技術提案

## バリューを発揮した点

### 軽量な設計プロセスとレビュー基準の導入による手戻り削減・リリース安定化

**■ 背景**
参画当初、明確な設計フェーズがなく、要件や仕様の認識差が実装段階になってから顕在化していた。

また、1 つの PR あたりの変更規模が大きく、レビュー負荷の高さや不具合の混入、リリース後の改修再発に時間が取られていた。

**■ 発揮したバリュー**
重い設計工程を入れても形骸化すると考え、チームが無理なく続けられる「最小限の設計ドキュメント + レビュー観点の固定 + PR の粒度基準」の 3 点に絞って仕組み化した。

■ 設計と PR 運用について意識した点

- 設計ドキュメントの最小化：事前に作るドキュメントを「API 仕様」と「データモデル」の 2 つだけに絞った
- 設計レビューの定例化と観点固定：「影響範囲」と「代替案」をレビューテンプレートに組み込み、承認基準を明確にした
- PR 運用の再設計：小さく早くマージする変更粒度の基準と、未レビューのコードはマージしないルールを徹底した
- ナレッジの一元化と定着：設計・決定事項・振り返りを Notion に集約し、月次の振り返りで運用を見直してチームに定着させた

■ 結果

実装前の事前合意によって仕様の不整合を早期に吸収できるようになり、要件起因の手戻りとリリース後の改修再発が大幅に減った。

また、PR あたりの変更ファイル数が縮小してレビュー時間が短縮され、設計からリリースまでのリードタイムが安定した。
→ [詳細](process.md)

### 電子同意書と電子カルテを繋ぐ連携 API のセキュリティ設計・実装

**■ 背景**
電子カルテ連携にあたり、セキュリティ要件が非常に厳しい医療機関への導入障壁をクリアする必要があった。

以降の医療機関への導入でも再利用できる標準手順と実装テンプレートを確立することが求められていた。

**■ 発揮したバリュー**
セキュリティ設計から実装、ベンダー折衝、現地での導入立会い、運用フローの整備までを単独で主導した。

インフラ制約で一般的な相互認証が使えない中、
アプリケーション層での証明書検証と API キーによる多層防御を設計した。

■ 具体的な取り組み

- 認証局の比較・選定と、電子カルテベンダーとの要件定義・仕様のすり合わせを主導した
- 鍵・証明書のローテーションを前提とした認証方式を設計・実装した
- 検証失敗を追跡できる監査ログと例外ハンドリングを標準化した

■ 結果

本番運用開始から 1 年間、セキュリティや連携に関するインシデント 0 を継続した。

医療機関での導入を現地立会いで成功させ、現場から「業務が効率化した」と高い評価を獲得するとともに、以降の医療機関向け連携の標準テンプレートとなった。
→ [詳細](api-cooperation.md)

### 説明動画配信基盤の刷新とオブザーバビリティ（監視・アラート）の強化

**■ 背景**
医療現場で使われる説明動画配信機能の再設計にあたり、期日内の確実なリリースと、障害発生時に即座に原因を特定できる運用基盤の強化が課題となっていた。

**■ 発揮したバリュー**
機能設計のリードだけでなく、設計段階から「運用時の検知性」を織り込むことで、サービスの安定稼働に貢献した。

■ 意識した点、具体的な取り組み

- 医療向け説明動画配信機能の再設計と基盤刷新をリードし、関係者と調整しながら期日内にリリースを完遂した
- 障害が起きた際にすぐ気づき、原因調査ができるよう、Cloud Logging・Sentry・Slack を用いたログ構造化、トレーシング、アラート通知を整備した
- 設計レビューの段階から監視・ログ出力の観点を組み込み、チーム全体で運用を意識した実装ができるように底上げした

## 使用技術

インフラ：Google Cloud（Cloud Run、Cloud SQL、Cloud Storage、Cloud Functions）

データベース：MySQL（Cloud SQL）

モニタリング：Cloud Logging、Sentry、Slack
