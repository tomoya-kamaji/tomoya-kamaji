### 背景と課題

企業側の主要機能であるユーザ検索は、従来 RDB の LIKE 句による部分一致で実装されていた。
そのため検索ノイズが多く、条件の追加で JOIN も肥大化してレスポンスが 2.0 秒まで悪化していた。
サーバサイドのリプレイスに合わせ、検索基盤から作り直すことにした。

### 判断

| 選択肢 | 評価 |
|---|---|
| RDB のチューニング | JOIN の複雑さと LIKE 句のノイズが残る |
| Elasticsearch に切り出す | 全文検索でノイズを抑えられ、検索ロジックも RDB から分離できる |

Elasticsearch への切り出しを選び、setting・mapping の設計からデータ投入バッチ、検索 API の実装までを一貫して担当した。
検索漏れとノイズの少なさを両立するため、analyzer には Ngram と Kuromoji を併用している。

- Ngram（必須条件 / must 句）：検索漏れを防ぐ
- Kuromoji（任意条件 / should 句）：形態素の一致でスコア（`_score`）を押し上げ、適合度の高い結果を上位に出す

### 成果

- 検索レスポンスを **2.0 秒から 0.5 秒に短縮**した
- 複雑な JOIN を RDB 側から剥がしたことで、検索 API のコードが簡潔になり条件追加もしやすくなった
