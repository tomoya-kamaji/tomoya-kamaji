### 概要

サーバサイドを Rails から Node.js（TypeScript）へ、DDD の思想を取り入れてリプレイスするプロジェクトに CTO と 2 人で取り組んだ。

### 設計で意識した点

作成・更新系はドメインモデル経由、参照系は専用モデルを直接返す CQS（コマンドクエリ分離）を取り入れた。
更新時はドメインルールによる整合性保護が必須だが、参照時はデータ不整合が起きない。
一覧 API は JOIN するテーブルが多く、無理にドメインモデルを通すと肥大化するため、参照と更新で経路を分けた。

### 成果

- CTO と 2 名でドメインモデル図・アーキテクチャ・テーブル・API の設計から実装までを担った
- 新規開発を止めず、約 1 年かけて約 120 エンドポイントをすべて移行した
- TypeScript と DDD は実務未経験だったが、公式ドキュメントと書籍でキャッチアップして移行の戦力になった
