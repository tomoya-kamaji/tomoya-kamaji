### 課題

複数のマイクロサービスで形態素解析器 Sudachi の処理が重複していたため、共通の gRPC サーバに切り出すことにした。

### 判断：言語の選定

| 候補 | 評価 |
|---|---|
| Go | プロダクトの標準言語だが、保守されたライブラリが無い（サードパーティ製も更新停止） |
| Java | ライブラリあり。性能も十分 |
| Python | ライブラリあり。性能も十分 |

性能差が無く、複雑なビジネスロジックも不要なため Python を採用した。

### 成果

Python・Docker・Terraform・GKE はほぼ実務未経験だったが、社内の既存サービスと書籍でキャッチアップし、約 3 週間で構築して本番投入した。

### 振り返り

利用者には AI エンジニアなど Go / gRPC に馴染みの薄いメンバーも含まれていた。スキーマ共有の手間を考えると、gRPC ではなくシンプルな REST API で提供すべきだった。
